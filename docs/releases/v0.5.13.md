# OpenCode/Kilo v0.5.13

This release adopts Sessionbus Go SDK v0.5.16 and bundled `@sessionbus/kit`
0.5.16. Product implementation, shared tool declaration, skills, native
permissions and path binding are unchanged from v0.5.12. The peer-common pin
stays at 29ddcb4585deaffc637163381ea1bce4a312e237. Native plugin package versions
retain their independent identities; no new runtime or sidecar is added.

Both SDKs now use `unknown_transfer` for a locally missing binding and for a
retained-ended binding after the existing checks. Existing path, field, role
and overwrite checks keep their current precedence and
`transfer_binding_conflict` refusals.

With a v0.5.16 local daemon, the kit negotiates `unknown_transfer` for status
of an inaccessible, absent or ended transfer. Older daemons retain the legacy
`transfer_failed` response. The hello result, federation errors and wire
Accept/Cancel behavior are unchanged. Against older daemons the optional hello
info key appears as ordinary public peer metadata. Unknown live status is not
terminal history, an outcome or authority to retry an uncertain transfer.

## Carried observations and remaining acceptance

The [v0.5.12 notes](v0.5.12.md) retain the bounded Linux UMKA observations at
4d4381cf with OpenCode 2.0.21 and Kilo 7.8.1. Those include matching file hashes,
streaming lifetime holds and close cancellation, same-task busy handling with
different native receipt labels, and Kilo's original request-lane failure
followed by its one authorized fresh-sender repeat. None is relabeled as a
kit16 run. U1–U5 are intended to carry through unchanged product code and the
reviewed kit delta.

Fresh kit16 interactive and lane U6 checks are NOT RUN: interactive absent
status followed by same-session list/send; lane native tool result followed by
collection/ack of its actual terminal and a continuity Run on the same lane.
The model's response to the wording is an observation, not a gate. A tool
refusal need not make the native Run unavailable.

The earlier [known issues](../KNOWN-ISSUES.md) and delivery limits remain.
Kilo custom-tool behavior under deny/ask remains unverified; the prior default
configuration observations do not establish it. Cross-host U7 and native macOS
checks remain unrun, with no full-matrix claim. Transfer filesystem access is
still direct OS-user access, with no native per-path approval. This release
adds no replay or recovery guarantee.
