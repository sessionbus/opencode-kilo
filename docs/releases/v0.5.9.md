# opencode-kilo v0.5.9

This release requires Sessionbus v0.5.9 (daemon and hub). It pins the Sessionbus Go SDK `v0.5.9`, and both native plugins pin `@sessionbus/kit` `0.5.9`. The version matches core v0.5.9. It is the first stable release from this repository and publishes `opencode-peer` and `kilo-peer` archives for Linux and macOS on amd64 and arm64, with `SHA256SUMS` and `SOURCE.txt`. The native plugin packages ship inside the archives.

**Breaking, a flag day.** The unreleased lane policy field `idle_message` is removed from the protocol, the SDK and the kit; message wake is mandatory. This peer requires a v0.5.9 daemon. Peers built with SDK or kit v0.5.7 or earlier are incompatible with it. Upgrade the hub, the host daemons and the product integrations together. Follow the upgrade steps, including the offline lane-row edit, in the [core v0.5.8 release notes](https://github.com/sessionbus/sessionbus/releases/tag/v0.5.8). v0.5.9 has the same runtime as v0.5.8.

Fixes:
- **`forget` keeps native history** (#5). Forgetting an existing or resumed OpenCode or Kilo lane no longer deletes the product-owned native session. Only the rollback of a failed fresh open still removes the session it just created.
- **An acknowledged permission rejection is a retained failed terminal** (#6). When the wrapper rejects a native permission request and native acknowledges it, a run that ends without a completed assistant returns `failed` with `OpenCode run ended by permission rejection` (or `Kilo …`). Before this, it returned `unavailable` (`native terminal lacks completed assistant`). A native error terminal or a completed assistant still takes precedence.
- **OpenCode busy-queued delivery waits for the halted assistant** (#7). Input queued while OpenCode is busy is handed off only after the active assistant's native completion and the idle that follows it. A halted turn publishes an earlier idle, and a prompt stored at that point never ran. Input that arrives while the session is idle is handed off directly. Kilo is unchanged.
- **An owner failure retires the lane with an ordinary self-close** (#8). When an adopted OpenCode or Kilo owner fails, the lane closes its own session through the normal close path instead of shutting the transport down at once. A pending `wait` therefore receives the `unavailable` record with the failure reason, not `-32002 not_connected`.

Limitations:
- **A failed owner can stay connected after a capacity Busy.** If the daemon answers the self-close Busy for capacity, the failed owner stays connected. The daemon's capacity Busy is identical on the wire to the Busy it returns for an already admitted close. A persistent lane then lingers until an explicit close, daemon shutdown or transport end. A non-persistent lane also ends with its parent.
- **OpenCode busy-queued handoff is best effort in two cases.**
  - The owner saw no assistant event for the turn, for example because it attached mid-step or missed events. It takes one bounded message snapshot. If the latest message is a user message or an already completed assistant, it cannot be ordered against the idle, and the input is handed off at that idle.
  - The owner missed the active assistant's completion event. The input is then not handed off at that idle. It stays in the bounded unsent queue until the owner observes a later completion followed by an idle.

  A handoff is `written`, not proof of model consumption. Attempted input is never replayed.

**Lanes without an explicit model use the native default.** A lane spawned without `open.model` runs the model that OpenCode's or Kilo's native configuration and plugins select by default. That model's provider must be configured, with credentials, on the host. The wrapper does not inherit the model displayed in a TUI and never substitutes another one.

`scripts/install-opencode.sh` and `scripts/install-kilo.sh` install the latest stable release by default, so they now install v0.5.9. This repository has no earlier stable release to pin, so run them only on hosts that are in their upgrade window.
