# OpenCode/Kilo v0.5.12

OpenCode and Kilo gain file transfers in interactive sessions and managed lanes.
Both use the complete shared Sessionbus tool declaration, with offer, request,
accept, cancel and status actions. Local paths bind to the native session's
verified directory; they do not use the helper process's working directory.
An unknown directory refuses relative paths while leaving absolute paths usable.

The SDK performs file I/O as the OS user, without a native sandbox or per-path
approval. Tightening transfer permissions remains open and is not a release
gate. Initial and terminal notices use the existing delivery path, including its
wake and admission limits. Lost or uncertain final results must not be retried
automatically. Transfers require v0.5.14 on all involved daemons and the hub.

The Go SDK is v0.5.14 and peer-common is pinned to merged
29ddcb4585deaffc637163381ea1bce4a312e237. The JavaScript kit is v0.5.15, including the shared
`Peer.closed` retirement correction. Final disposal awaits that public
promise; the wrapper does not maintain a second transfer registry. Availability
and policy negotiation also comes from the SDK: list results can expose a silent
host as `availability: "not_responding"`, and policy refusals remain visible.

## Carried changes since the previous tag

These results are historical evidence for those fixes, not transfer acceptance.

## Validation status and limits

The permanent 4d4381cf installation on Linux UMKA was exercised with OpenCode
2.0.21 and Kilo 7.8.1, daemon and JavaScript kit 0.5.15. Later test and documentation
corrections do not change those installed runtime bytes. OpenCode used the
configured DeepSeek V4 Pro through native per-session selection after its
Gemini default lacked a key. Kilo initially used its native Auto Free gateway
models; after that gateway required sign-up, its remaining streaming-close and
busy-message checks used the configured DeepSeek V4 Pro through native selection.
No provider configuration, login or native permission policy was changed.

Both products completed interactive offer/accept and an idle lane's request/accept
with matching 1 MiB hashes. Cancellation, refusal to overwrite an existing file,
explicit overwrite and absent-ID status refusal followed by ordinary tool use
were observed. Kilo's first request-lane attempt failed after its model rewrote
the lane instructions and attempted to accept in the wrong role; that failure remains in
the record. One authorized fresh-sender repeat passed with the supplied lane
input. Invalid tool arguments and extra model status polls remain recorded,
not silently converted to successful transfers.

A 1 GiB stream kept each product's lane connected beyond its 1000 ms post-Run
grace. Closing the lane cancelled the transfer, with no destination or temporary
file remaining. Both products acknowledged a busy message at the next model step of the same
ongoing streaming-check task (OpenCode receipt `injected`; Kilo receipt
`queued_for_next_turn` with in-task placement). Idle notice wake and collected lane Runs were
also observed. Native permission prompts occurred for Kilo's separate shell hash
and sleep commands, not for Sessionbus calls, including transfer actions. This
is evidence for the tested default configuration only.

All owned test lanes and TUIs were closed; the OpenCode service retained its two
peer rows under the existing native-dormant lifecycle. Fixture postflight checks
found zero transfer temporary files. Cross-host transfers (U7) and native macOS
checks were not run; this is not full-matrix acceptance. Local suites, independent
reviews and hosted CI are recorded separately from these native observations.

Shared error-wording defects remain open: daemon status on an ended or absent
transfer returns generic `transfer_failed`, and both SDKs use
`transfer_binding_conflict` for a locally unknown ID. Models can misread these
refusals as an actual transfer failure or collision. Valid role/field refusals
are separate and remain correct. The observed terminal notices and file hashes
establish outcomes; this release does not fix the misleading wording or make
uncertain transfers safe to retry.

The earlier [known issues](../KNOWN-ISSUES.md) and documented delivery limits
remain. The held skill paragraph is unchanged; only the opening action list
adds the five transfer names. Kilo native custom-tool behavior under a user
`deny` or `ask` configuration has not been established by the wrapper source
read. This is unverified comms-rule coverage, not a confirmed defect; existing
default-config live calls are separate evidence.

The archive version is v0.5.12. Native plugin package versions remain their
existing independent identities.
